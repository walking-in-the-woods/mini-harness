# Prompt-файлы

## Что это

Файл с текстовой инструкцией, который подставляется модели вместо
встроенного system-промпта в guided mode. Позволяет задавать
специфические правила для конкретного типа задачи (описать проект,
перевести строго по глоссарию, извлечь структуру) — без правки
Python-кода.

Prompt-файл — это **данные**, не код. Его можно менять, коммитить,
тестировать как обычный текст. Harness не перезапускается.

## Синтаксис

Два способа указать prompt-файл в запросе.

### 1. Явный маркер

```sh
>>> прочитай input/_tree_harness.md согласно инструкции из input/prompts/tree-summary.md, результат в output/overview.md
```

Поддерживаемые маркеры:

| Маркер | Пример |
| --- | --- |
| `по инструкции из` | `…согласно инструкции из input/prompts/x.md` |
| `согласно инструкции` | `…по инструкции input/prompts/x.md` |
| `с промптом` / `по промпту` | `…прочитай input/a.md с промптом input/prompts/x.md` |
| `using prompt` / `with prompt` | `…read input/a.md using prompt input/prompts/x.md` |
| `following prompt` / `per prompt` | `…summarize input/a.md following prompt input/prompts/x.md` |

### 2. Соглашение `input/prompts/`

Любой путь под `input/prompts/` автоматически считается prompt-файлом,
даже без маркера:

```sh
>>> прочитай input/_tree_harness.md и примени input/prompts/tree-summary.md, результат в output/overview.md
```

Это работает и когда в запросе нет ключевого слова операции —
операция становится `custom`, guided mode запускается с prompt-файлом.

## Как это работает

1. Парсер извлекает из запроса три роли: **source**, **target**, **prompt**.
2. Harness читает prompt-файл и **полностью заменяет** им слот `system`.
3. В конец system добавляется `/no_think` — для qwen3 это активатор
   режима без reasoning на уровне chat-template.
4. Модель получает **один** вызов без tools.
5. Результат пишется в target через обычный nonce.

Проверить, что prompt-файл подхватился, можно по строке в stderr:

```text
[*] guided mode: custom input/_tree_harness.md -> output/overview.md [prompt: input/prompts/tree-summary.md]
[*] custom model output: '...' (N chars)
```

## Reasoning-leakage

Некоторые модели (qwen3:4b и родственные) при `think=False` всё
равно выводят цепочку рассуждений как обычный текст: «Хорошо, мне
нужно описать проект…», «Сначала определю…». Это не сбой harness —
это ограничение модели.

Harness смягчает двумя механизмами:

1. **`/no_think`** в system-промпте. Для qwen3 это активатор режима
   без reasoning. Если он не помогает — модель игнорирует, и это
   её предел.
2. **Детектор + retry.** `_looks_like_reasoning` проверяет первую
   строку на мета-маркеры и считает их частоту. При срабатывании —
   один retry с усилителем. Если и retry дал reasoning — **жёсткий
   отказ**: файл не записывается, nonce не показывается.

Практический вывод: с `qwen3:4b` в guided mode может не получиться.
С `qwen2.5:7b-instruct`, `llama3.2:3b` — обычно получается.

## Потолок модели

Результат нескольких итераций:

| Модель | Промпт | Результат |
| --- | --- | --- |
| qwen3:1.7b | минимальный без примеров | 3 из 4 директорий правильные, `sources/` синтетическая |
| qwen2.5-coder:3b | с примерами | копия примера дословно |
| llama3.2:3b | с примерами | копия примера дословно |
| qwen3:4b | минимальный | reasoning-leakage, 6.6 КБ самодиалога |

**Правила для prompt-файлов при работе с моделями < 4B:**

1. Никаких примеров — копируются дословно, независимо от метки.
2. Никаких списков и нумерации — воспроизводятся как заголовки.
3. Прозой, не bullet-поинтами.
4. Минимум правил — одно работает, пять не работают.
5. Запреты работают лучше разрешений.
6. Явный язык ответа.

## Как писать свой prompt-файл

1. **Одна тема — одно предложение инструкции.**
2. **Императив, прозой.**
3. **Запреты в конце** — их модель читает внимательнее.
4. **Не давайте примеров для моделей < 4B.** Для 4B+ можно.
5. **Явный язык.** «На русском языке».
6. **Тестируйте на своём источнике.**

## Что не поддерживается

- **Несколько prompt-файлов.** Только один.
- **Промпт-файлы для `/tree`, `/files`, `/dump`.**
- **Многошаговые prompt-файлы** («сначала сделай X, потом Y»).
- **Few-shot примеры для моделей < 4B.**

# Политики доступа к файлам

Правится в `config.yaml`, секция `fs`. Правки подхватываются при
новом запуске REPL.

## Четыре списка

```yaml
fs:
  whitelist:
    - "**"

  blacklist:
    - "**/.git/**"
    - "**/*.key"

  writable:
    - "output/**"
    - "output/code/**"
    - "notes/**"
    - "*.md"
    - "*.txt"

  ext_allow_paths:
    - "output/code/**"
```

- **`whitelist`** — что модель может видеть вообще. Если файл не
  матчится ни одним шаблоном, доступа нет (read и write).
  **Пустой список означает «ничего не разрешено».** Отсутствие ключа
  даёт дефолт `["**"]`.
- **`blacklist`** — что запрещено, даже если прошло whitelist.
  Применяется после whitelist. Пустой список = ничего не запрещено.
- **`writable`** — что модель может предлагать к записи. Пустой
  список = запись везде запрещена. На чтение не влияет.
- **`ext_allow_paths`** — исключения из `WRITE_EXT_BLOCK`. Если путь
  матчится хотя бы одним шаблоном, заблокированное расширение
  разрешается. **Пустой список или отсутствие ключа = все
  расширения из `WRITE_EXT_BLOCK` запрещены, как раньше.**

## Glob-синтаксис

| Шаблон | Матчит |
|---|---|
| `*` | один сегмент, кроме `/` |
| `**` | любое число сегментов, включая ноль |
| `?` | один символ, кроме `/` |
| `docs/**` | всё внутри `docs/`, но не сам `docs` |
| `**/*.md` | любой `.md` на любой глубине |
| `*.md` | только `.md` в корне `workspace/` |

## Расширения на запись

`WRITE_EXT_BLOCK` в `harness/fs_guard.py`:

- `.sh`, `.bash`, `.zsh`, `.fish`, `.ksh`
- `.exe`, `.bat`, `.cmd`, `.ps1`, `.vbs`
- `.py`, `.js`, `.ts`, `.rb`, `.go`, `.rs`, `.lua`
- `.php`, `.jsp`, `.cgi`, `.pl`
- `.whl`, `.egg`

Модель может **читать** любые из них. Запись блокируется, если путь
не входит в `ext_allow_paths`.

## Как разрешить запись кода

Три шага:

1. **Создать директорию.** Например, `workspace/output/code/`. Она
   создаётся автоматически через `scripts/setup-workspace.sh`.

2. **Добавить в `writable`.** Без этого запись не пройдёт, даже с
   `ext_allow_paths` — это защита от опечаток.

3. **Добавить в `ext_allow_paths`.** Здесь снимается блокировка
   расширений.

```yaml
fs:
  writable:
    - "output/code/**"
  ext_allow_paths:
    - "output/code/**"
```

После этого модель может писать `output/code/counter.py` через
`propose_write`. Nonce-подтверждение работает как обычно.

## Что ext_allow_paths НЕ делает

- **Не обходит whitelist.** Если путь не разрешён для чтения —
  запись тоже невозможна.
- **Не обходит blacklist.** `**/secret.py` в blacklist останется
  запрещённым, даже если в `ext_allow_paths`.
- **Не отменяет `writable`.** Путь должен быть в `writable` явно.
- **Не даёт модели права писать код куда угодно.** Только в
  директорию, которую вы явно указали.

Это три независимых фильтра, применяемых последовательно:
`whitelist → blacklist → extension → writable`. `ext_allow_paths`
влияет только на шаг `extension`.

## Типовые конфигурации

**Только текст (по умолчанию):**

```yaml
writable:
  - "output/**"
  - "notes/**"
  - "*.md"
  - "*.txt"
# ext_allow_paths отсутствует — код писать нельзя нигде
```

**Текст + код в отдельной директории:**

```yaml
writable:
  - "output/**"
  - "output/code/**"
  - "notes/**"
  - "*.md"
  - "*.txt"
ext_allow_paths:
  - "output/code/**"
```

**Код для конкретного языка:**

```yaml
ext_allow_paths:
  - "output/code/python/**"   # только .py
  - "output/code/shell/**"    # только .sh
```

Нельзя ограничить по расширению внутри `ext_allow_paths` — механизм
снимает блокировку для всех `WRITE_EXT_BLOCK` сразу. Если нужно
более точечное управление, придётся править `WRITE_EXT_BLOCK` в
`fs_guard.py`.

## Подводные камни

- **`workspace/` не должен быть симлинком на `$HOME`.** Guard
  развернёт symlink и откажет, но лучше не проверять.
- **Уже существующие файлы.** Guard проверяет только то, что модель
  **предлагает записать** — за чистоту уже лежащих в workspace
  файлов отвечает пользователь.
- **Проверка на чтение не зависит от существования файла.**
  `check_read` возвращает `True` для несуществующего файла, если
  путь разрешён. Отсутствие файла обнаруживает tool.

## Как расширить

**Добавить разрешение на запись в новую папку:**

```yaml
writable:
  - "output/**"
  - "notes/**"
  - "drafts/**"       # ← добавили
  - "*.md"
```

**Убрать `Makefile` из чёрного списка:**

```yaml
blacklist:
  - "**/.git/**"
  # - "**/Makefile"     # закомментировано
```

**Разрешить только конкретный подкаталог:**

```yaml
whitelist:
  - "input/**"
  - "output/**"
```

После правки — новый REPL.

# Batch-режим

## Что это

Обработка директории файлов одним prompt-файлом. Каждый файл
трансформируется независимо, без tools, с той же логикой
reasoning-retry, что и одиночный guided mode.

Типичные задачи:

- Добавить docstrings во все Python-модули проекта.
- Перевести все `.md` файлы директории на другой язык.
- Извлечь структуру из набора текстовых файлов.
- Переписать все файлы в едином стиле.

## Команда

```sh
/batch <source_dir> <glob> <prompt_path> [<target_dir>]
```

| Аргумент | Обязателен | Что |
| --- | --- | --- |
| `source_dir` | да | директория с исходными файлами |
| `glob` | да | паттерн для имён файлов: `*.py`, `test_*.md` |
| `prompt_path` | да | prompt-файл (один на весь batch) |
| `target_dir` | нет | куда писать результат |

Если `target_dir` не указан, используется
`output/batch/<YYYY-MM-DD-HHMMSS>/`.

Пример:

```sh
/batch input/batch '*.py' input/prompts/add-docstrings-generic.md
```

Glob работает по именам файлов, не по путям. `*.py` матчит все
`.py` в `source_dir`, но не рекурсивно. `**/*.py` не поддерживается —
плоская структура, без вложенных директорий.

## Как это работает

1. Harness читает prompt-файл.
2. Собирает список файлов по `source_dir` + glob.
3. Для каждого файла:
   - читает содержимое,
   - проверяет, что target writable,
   - вызывает модель БЕЗ tools с содержимым и prompt-файлом в system,
   - при reasoning-leakage — один retry с усиленным prompt.
4. Показывает preview всех items с их статусами.
5. Ждёт ввода: nonce или `N skip`.
6. При nonce — записывает все успешно трансформированные items.

## Preview

```sh
================================================================
 BATCH PREVIEW — 3 items
================================================================

  [ ]  1. input/batch/sample_a.py                213 chars
  [ ]  2. input/batch/sample_b.py                287 chars
  [ ]  3. input/batch/sample_c.py                198 chars

Будет записано: 3 из 3

================================================================
 Введите код для применения: 4F7A2C19
 '<номер> skip' — исключить файл из записи
 Любой другой ввод — отмена
================================================================
```

Маркеры:

| Маркер | Значение |
| --- | --- |
| ` ` | будет записан |
| `x` | пропущен (skip) |
| `!` | провален при трансформации |

## Skip и restore

```sh
code> 2 skip
[+] item 2 исключён из записи
code> 2 skip
[+] item 2 снова участвует в записи
code> 4F7A2C19
[*] Применяю batch...
  [+] output/batch/2026-09-17-143022/sample_a.py (213 chars)
  [+] output/batch/2026-09-17-143022/sample_c.py (198 chars)
[OK] Записано: 2, ошибок: 0
```

Skip работает как переключатель. Проваленные items пропустить
нельзя — они и так не будут записаны.

Отмена — любой ввод, кроме nonce и `<N> skip`. Ничего не пишется.

## Skip-and-continue

Провал одного файла не прерывает batch. Возможные причины провала:

- Reasoning-leakage после retry (для `qwen3:4b` и родственных).
- Пустой ответ модели.
- Файл слишком большой для `NUM_CTX`.
- Target не в `writable` или в `WRITE_EXT_BLOCK`.

Провалившиеся items остаются со статусом `failed`, помечаются `!`
в preview и не записываются. Batch продолжается.

## Куда пишется

Default: `output/batch/<timestamp>/`. Timestamp — момент запуска,
формат `YYYY-MM-DD-HHMMSS`. Каждый batch — в своей директории,
предыдущие не перезаписываются.

Структура источника сохраняется относительно `source_dir`:

```sh
input/batch/sample_a.py    -> output/batch/2026-09-17-143022/sample_a.py
input/batch/sample_b.py    -> output/batch/2026-09-17-143022/sample_b.py
```

Source никогда не перезаписывается.

## Ограничения

- **Плоская структура.** Файлы ищутся только в `source_dir`,
  без рекурсии по подкаталогам. Для вложенных структур —
  `/batch` на каждый подкаталог вручную.
- **Один prompt на весь batch.** Заменить промпт между items нельзя.
- **Последовательно.** Items обрабатываются по одному. Параллельный
  запуск на 8 ГБ RAM бессмысленен: модель одна, память под неё одна.
- **Время.** N файлов × 1–2 минуты на 3B-модели. 20 файлов = ~30–40
  минут. При `_BIG_BATCH_WARN=20` печатается предупреждение.
- **Размер каждого файла** ограничен `HARNESS_MAX_READ_BYTES`
  (200 КБ по умолчанию). Файлы больше не читаются.
- **Размер каждого файла в контексте** ограничен `NUM_CTX`.
  Файл + prompt должны укладываться в контекст модели.

## Что НЕ делает batch

- **Не делит длинный файл на chunks.** Если файл не помещается в
  контекст — batch пропустит его с ошибкой. Для длинных файлов
  нужен отдельный режим (скользящее окно), не реализован.
- **Не обрабатывает рекурсивно.** Только файлы в `source_dir`.
- **Не делает dry-run.** Preview показывается после трансформации.
- **Не сохраняет состояние между запусками.** Прерванный batch
  нельзя продолжить — запускается заново.

## Что делать после batch

Результаты в `output/batch/<timestamp>/`. Их можно:

- Прочитать вручную и скопировать в исходный проект.
- Прогнать через guided mode для дополнительной обработки.
- Сравнить с оригиналом (`diff -ru input/batch output/batch/.../`).

## Безопасность

- **Source читается через fs_guard.** Blacklist и whitelist
  применяются к каждому файлу.
- **Target проверяется дважды** — при трансформации и перед
  записью. TOCTOU defense.
- **WRITE_EXT_BLOCK действует.** Для `.py` в target нужен либо
  `ext_allow_paths`, либо `.txt`-обёртка.
- **Nonce один, но он подтверждает N файлов.** Пользователь видит
  все diff'ы в preview — точнее, все размеры и имена. Полное
  содержимое каждого файла не показывается, но по размерам и
  статусам видно, что batch не провалился.
- **Audit.** События `batch_transformed`, `batch_applied`,
  `batch_cancelled`, `batch_item_failed`, `batch_retry` пишутся в
  `logs/audit.jsonl`.

## Пример: добавить docstrings во все .py в директории

Файл `workspace/input/prompts/add-docstrings-generic.md`:

```markdown
Добавь каждой функции в файле docstring в формате Google-style.

Структура docstring: краткое описание (одна строка), затем блок
Args с параметрами и их типами, затем блок Returns с типом и
описанием. Если функция может выбросить исключение — блок Raises.

ВАЖНО: выведи ВЕСЬ файл целиком, включая импорты и весь
существующий код без изменений. Не сокращай. Не переписывай тело
функций — только добавь docstring сразу под строкой def.

Выведи только Python-код, без markdown-обёртки и без пояснений.
```

Файлы для обработки лежат в `workspace/input/batch/`:

- `sample_a.py` — 2 функции
- `sample_b.py` — 2 функции
- `sample_c.py` — 2 функции

Команда:

```sh
/batch input/batch '*.py' input/prompts/add-docstrings-generic.md
```

Результат — в `output/batch/<timestamp>/`.

# Использование

## Запуск

```bash
./run.sh
```

Первый запуск создаст `.venv`, установит зависимости, скопирует
`.env.example` в `.env` и создаст дерево `workspace/`.

## Рабочая папка

```
workspace/
├── input/    ← сюда кладёте файлы (модель читает, не пишет)
├── output/   ← сюда модель пишет результат
├── notes/    ← черновики (writable)
├── drafts/   ← черновики (writable)
```

`input/` специально исключён из `writable` — исходники остаются
нетронутыми.

## Типичный сценарий

```
>>> прочитай input/report.md и напиши краткое резюме в output/summary.md

--- MODEL ---
Файл ожидает подтверждения.

============================================================
 PENDING WRITES — ПРОВЕРЬТЕ ПЕРЕД ПОДТВЕРЖДЕНИЕМ
============================================================
--- output/summary.md ---
[NEW FILE, 412 bytes]
# Краткое резюме
...
============================================================
 Введите код для ПРИМЕНЕНИЯ: 4F7A2C19
============================================================

code> 4F7A2C19
[OK] output/summary.md (412 bytes)
```

Результат сразу лежит на хосте: `cat workspace/output/summary.md`.

## Несколько задач в одной сессии

Лимиты: **одна запись на сессию** и **read-after-write block**
(в текущей сессии нельзя прочитать только что записанный файл).
Между задачами — `/reset`:

```
>>> /reset
>>> прочитай output/summary.md и добавь раздел «Рекомендации»
```

## Отказ от записи

Если ввести не код, а что-то другое — файл не создаётся, состояние
не меняется. Это ожидаемое поведение.

## Команды REPL

| Команда | Действие |
|---|---|
| `/quit` | Выход |
| `/reset` | Новая сессия |
| `Ctrl+C` | Прерывание ввода |

## Лимиты

| Что | Где меняется | Дефолт |
|---|---|---|
| Раундов tool-loop | `HARNESS_MAX_TOOL_ROUNDS` | 4 |
| Размер файла на чтение | `HARNESS_MAX_READ_BYTES` | 200 000 |
| Размер `propose_write` | `HARNESS_MAX_WRITE_BYTES` | 1 000 000 |
| Элементов в `list_dir` | `HARNESS_MAX_LIST_ENTRIES` | 500 |
| Размер контекста | `HARNESS_NUM_CTX` | 2048 |
| Макс. токенов ответа | `HARNESS_NUM_PREDICT` | 1024 |

Правки — в `.env`, подхватываются при новом запуске.

## Логи

```bash
# Что модель делала
tail -f logs/audit.jsonl

# Красиво
tail -f logs/audit.jsonl | python3 -m json.tool --json-lines 2>/dev/null \
  || tail -f logs/audit.jsonl
```

## Что не работает

- **«Отредактируй все файлы в input/»** — упадёт на лимите одной
  записи в сессии. Разбивайте на несколько сессий.
- **«Запусти скрипт»** — модель не выполняет код. Может подготовить
  `.txt` со скриптом, вы запустите вручную.
- **«Пойди в интернет и найди»** — без явного route в `api_call`
  модель не имеет доступа к сети.
- **PDF/DOCX/PNG.** Только UTF-8 текст. Конвертируйте заранее.

# Архитектура

## Компоненты

Всё работает в одном Python-процессе. Отдельно от него — только
сервер инференса, установленный на машине.

```
┌─────────────────────────────────────────────────────────┐
│  python -m harness.main (один процесс)                  │
│                                                          │
│  ┌────────────┐  ┌──────────────┐  ┌────────────────┐   │
│  │ FileSystem │  │ Injection    │  │ ConfirmSession │   │
│  │ Guard      │  │ Guard        │  │ (nonce, diff)  │   │
│  └────────────┘  └──────────────┘  └────────────────┘   │
│                                                          │
│  ┌────────────┐  ┌──────────────┐  ┌────────────────┐   │
│  │ Harness    │  │ ApiProxy     │  │ AuditLog       │   │
│  │ Agent      │  │ (httpx)      │  │ (JSONL)        │   │
│  └─────┬──────┘  └──────┬───────┘  └────────────────┘   │
│        │                │                                │
└────────┼────────────────┼────────────────────────────────┘
         │                │
         │ HTTP           │ HTTPS
         │ (tool calls)   │ (whitelisted routes)
         ▼                ▼
   ┌──────────┐     ┌───────────────┐
   │ Локальный│     │ Внешние API   │
   │ сервер   │     │ (фикс. хосты) │
   │ инференса│     └───────────────┘
   └──────────┘
```

## Поток одного запроса

1. Пользователь вводит текст в REPL (`harness/main.py`).
2. `HarnessAgent.run()` проверяет ввод через `InjectionGuard`.
3. Формируется контекст: системный промпт + сообщение пользователя.
4. Цикл до `max_tool_rounds`:
   - модель возвращает текст и/или `tool_calls`;
   - каждый `tool_call` проходит `_dispatch`, результат
     оборачивается в `<tool_result trust="untrusted">`;
   - результат добавляется как сообщение роли `tool`.
5. Если модель вызвала `propose_write` — запись кладётся в очередь,
   цикл завершается.
6. REPL показывает diff и ждёт nonce.
7. `ConfirmSession.apply()` повторно проверяет `check_write`
   (TOCTOU defense), пишет через `mkstemp` + `os.replace`.

## Компоненты

### `FileSystemGuard`

Проверяет каждый путь:
- NFKC-нормализация (гомоглифы);
- запрет `..` и `\x00`;
- `os.path.realpath` разворачивает symlink-цепочку;
- проверка, что результат остаётся под `workspace/`;
- whitelist → blacklist последовательно;
- для записи — дополнительно: `writable`, `WRITE_EXT_BLOCK`.

### `InjectionGuard`

- `is_suspicious()` — эвристики на пользовательский ввод.
- `neutralize_data_block()` — экранирует XML-теги ролей, тройные
  бэктики в данных из инструментов.
- `scan_payload()` — опасные конструкции в содержимом, которое
  модель предлагает записать.

### `ConfirmSession`

- Генерирует nonce (`secrets.token_hex`).
- Показывает unified diff (для существующих файлов) или полное
  содержимое (для новых).
- `apply()` принимает код, сверяет через `secrets.compare_digest`,
  повторно проверяет путь и пишет атомарно.

### `AuditLog`

- JSONL, пишется вне `workspace/`.
- `fsync` для критичных событий, `flush` — для остальных.
- Пути в логе **не редактируются**: если файл называется
  `notes/клиент_Иванов.md`, имя попадёт в лог.

### `ApiProxy`

- Хост берётся из `config.yaml:proxy.routes`, не из аргументов модели.
- `follow_redirects=False`.
- Лимиты на request/response body.
- Таймаут из `HARNESS_PROXY_TIMEOUT`.

### `HarnessAgent`

- Tool-loop с жёстким лимитом `HARNESS_MAX_TOOL_ROUNDS`.
- `_written_paths` хранит канонические пути — блокирует
  read-after-write.
- `_redact_args` скрывает `content`, `body`, `params` перед записью
  в audit.

## Границы доверия

| Доверяем | Не доверяем |
|---|---|
| Хост и пользователь | Содержимое файлов в `workspace/` |
| Код harness (сами писали) | Генерация модели |
| Маршруты из `config.yaml` | Аргументы tool_call от модели |
| Пользовательское подтверждение записи | Ответы внешних API |

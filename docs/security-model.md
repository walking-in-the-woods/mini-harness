# Модель угроз

## Активы

- **Файлы вне `workspace/`.** Не должны быть доступны модели.
- **Секреты в `workspace/`.** Не должны утекать через чтение или
  через записанный файл.
- **Целостность `workspace/`.** Записи вне разрешённых путей быть
  не должно.
- **Целостность контекста модели.** Данные из инструментов не должны
  интерпретироваться как инструкции.

## Акторы

- **Пользователь.** Доверенный, но не всеведущий: может не заметить
  подозрительный diff.
- **Модель.** Не доверяем. Может быть подсказана инъекцией или
  сама ошибиться.
- **Содержимое `workspace/`.** Не доверяем.
- **Внешние API.** Не доверяем.

## Что защищено

### Файловая система

| Угроза | Защита |
|---|---|
| `../../../etc/passwd` | Запрет `..` + `realpath` + проверка префикса |
| Symlink на `/etc` | `os.path.realpath` разворачивает цепочку |
| Гомоглифы (`а` vs `a`) | NFKC-нормализация до сравнения |
| Null-byte в пути | Явная проверка `\x00` |
| Запись `.sh`/`.py` | `WRITE_EXT_BLOCK` |
| Запись `.bashrc`/`Makefile` | Чёрный список |
| Опасный payload под `.txt` | `scan_payload` по регуляркам |
| DoS через большой файл | `HARNESS_MAX_READ_BYTES` |

### Контекст и инъекции

| Угроза | Защита |
|---|---|
| «Ignore previous instructions» в файле | `<tool_result trust="untrusted">` + правило в системном промпте |
| XML-теги ролей в данных | `neutralize_data_block` экранирует расширенный набор |
| Тройные бэктики в данных | Заменяются на `'''` |
| Самоинъекция через записанный файл | `_written_paths` + read-after-write block |
| Обфускация невидимыми символами | Удаление zero-width, bidi, variation selectors |
| Гомоглифы в тексте | Транслитерация кириллица/греческий/fullwidth |

### Запись

| Угроза | Защита |
|---|---|
| Программный вызов `confirm(True)` | `ConfirmSession.apply()` требует nonce |
| TOCTOU между показом и записью | Повторный `check_write` **после** подтверждения |
| Полузаписанный файл при сбое | `mkstemp` + `os.replace` |
| Неожиданные права | Явный `chmod 0o644` |

### Внешние API

| Угроза | Защита |
|---|---|
| SSRF через подстановку хоста | Хост из `routes`, не из аргументов |
| Redirect на внутренний адрес | `follow_redirects=False` |
| DoS через большой запрос/ответ | `HARNESS_PROXY_MAX_*` |

## Что осознанно НЕ защищено

- **Сетевая изоляция модели.** Процесс инференса работает как
  отдельный сервис на хосте и имеет доступ в интернет. В
  контейнерной версии это закрывалось пятью Docker-сетями; в mini
  мы этим жертвуем ради памяти.
- **Аутентификация клиентов.** Один пользователь на машине.
  Нет mTLS, нет токенов, нет rate limiting.
- **Container hardening.** Процесс harness работает от вашего
  пользователя. Compromise Python-процесса = compromise вашего
  пользователя.
- **Отложенное исполнение.** Файл `.txt` с `sleep 3600 && rm -rf`
  не блокируется: он не `.sh`.
- **Пользователь, читающий diff невнимательно.** Если вы ввели
  nonce, не посмотрев diff — файл записан.
- **Компрометация хоста.** Если атакующий уже имеет доступ к
  пользователю, mini-harness не даёт дополнительной защиты.

## Что делать при чувствительных данных

1. **Разместить `workspace/` на отдельном разделе.**
2. **Не класть секреты в `workspace/`** — всё оттуда читается.
3. **Периодически смотреть `logs/audit.jsonl`** на неожиданные
   `propose_write`.
4. **Проверять diff** перед вводом кода подтверждения.
5. **Не запускать одновременно несколько инстансов** на одном
   `workspace/` — сессии не координируются.

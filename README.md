# Mini Harness

Упрощённая версия paranoid-harness для слабых машин (8–16 ГБ RAM,
~1.5 ГБ свободно под модель). Без Docker, без mTLS, без гейтвея.
Один Python-процесс, локальный сервер инференса, одна модель.

Поддерживаются два бэкенда инференса:

- **Ollama** (по умолчанию) — нативный `ollama serve`.
- **llama.cpp** — OpenAI-совместимый `llama-server`, собранный
  под конкретный CPU (см. `docs/backends.md`).

Выбор бэкенда — одной переменной в `.env`. Всё остальное (политики
путей, guided mode, batch, аудит) работает одинаково.

## Что осталось от защиты

- **Файлы** — только внутри `./workspace`, whitelist/blacklist/writable,
  защита от traversal, symlink escape, NFKC-гомоглифов.
- **Запись** — только с подтверждением одноразовым кодом,
  одна на сессию, атомарная, `chmod 0o644`.
- **Read-after-write block** — записанный в этой сессии файл нельзя
  прочитать в той же сессии.
- **Инъекции** — все tool-результаты проходят нейтрализацию тегов;
  XML-теги ролей экранируются, тройные бэктики заменяются.
- **Внешние API** — только через маршруты из `config.yaml`.
  Хост берётся из конфига, не из аргументов модели.
- **Аудит** — `logs/audit.jsonl`, `fsync` для критичных событий.

## Что потеряно (осознанно)

- Нет сетевой изоляции процесса инференса. Он имеет доступ в интернет.
- Нет аутентификации клиентов — один пользователь на машине.
- Нет container hardening — процесс работает от вашего пользователя.

Модель угроз: одна машина, один оператор, `workspace/` не содержит
чужих данных. Для этого профиля оставленной защиты достаточно.

## Какой бэкенд выбрать

| Сценарий | Бэкенд |
| --- | --- |
| Уже стоит `ollama serve`, модели тянутся через `ollama pull` | **ollama** |
| Свой CPU, хочется собрать `llama.cpp` под AVX2/FMA/F16C | **llamacpp** |
| Хочется Web UI на порту 8080/8082 (встроен в `llama-server`) | **llamacpp** |
| Нужен нативный `think=False` для qwen3 (reasoning-leakage) | **ollama** |
| Минимум зависимостей: никакого Python-клиента к серверу | **llamacpp** |

Детали и подводные камни — в `docs/backends.md`.

## Установка

1. Убедитесь, что локальный сервер инференса запущен и модель из
   `.env` загружена.
   - Для ollama: `ollama serve` и `ollama pull <model>`.
   - Для llama.cpp: `~/Desktop/run-coder3b.sh` или `run-coder7b.sh`
     (см. инструкцию по сборке, которая входит в проект).
2. Запуск:

   ```bash
   chmod +x run.sh
   ./run.sh
   ```

   Первый запуск создаст `.venv`, поставит три зависимости, создаст
   `workspace/{input,output,notes,drafts}` и `logs/`.

## Использование

```sh
>>> прочитай input/report.md и напиши резюме в output/summary.md
```

При предложении записи покажется diff и одноразовый код. Введите код —
файл запишется. Введите что-то другое — отмена.

- `/quit` — выход
- `/reset` — новая сессия

## Запуск моделей

Для Ollama — `ollama serve` + `ollama pull <model>`.

Для llama.cpp — единый скрипт `scripts/llama-server.sh`:

```bash
# Запустить модель и переключить .env одной командой
scripts/llama-server.sh use 4b

# Список моделей и портов
scripts/llama-server.sh list

# Остановить
scripts/llama-server.sh stop 4b
```

Полная инструкция, таблица моделей, автоматический выбор порта и
полный цикл batch-проверки — в [scripts/README.md](scripts/README.md).

## Настройка

Все скалярные параметры — в `.env`. Политики путей и маршруты
внешних API — в `config.yaml`. Правки подхватываются при новом запуске.

**Выбор бэкенда:**

```env
HARNESS_BACKEND=ollama       # или llamacpp
```

**Для машин с ограниченной памятью (Ollama):**

- `HARNESS_NUM_CTX` — главный параметр по расходу RAM. Уменьшение с
  2048 до 1024 ощутимо снижает KV-cache.
- `HARNESS_KEEP_ALIVE` — модель выгрузится через указанное время
  бездействия и освободит RAM.
- `HARNESS_NUM_PREDICT` — ограничение длины ответа.
- `HARNESS_MAX_TOOL_ROUNDS` — для небольших моделей значение 4 обычно
  безопаснее, чем больше: они начинают выдумывать после 3–4 раундов.

**Для llama.cpp:** `NUM_CTX` и `KEEP_ALIVE` игнорируются, потому что
контекст задаётся флагом `--ctx-size` при запуске сервера, а модель
всегда в RAM (или в mmap). Согласуйте `HARNESS_NUM_CTX` в `.env`
с `--ctx-size` скрипта запуска вручную. `LLAMACPP_TIMEOUT` держите
на 300 секунд — на N100+7B Q4 один ответ генерируется 4–8 минут.

## Что делать при проблеме

- **`[backend error]`** — сервер не запущен, недоступен по адресу
  из `.env`, или модель не загружена.
- **`[BLOCKED]`** — ввод похож на инъекцию. Переформулируйте.
- **`ACCESS DENIED`** — путь в blacklist или вне whitelist.
- **`REJECTED: extension ...`** — сохраняйте скрипты как `.txt`.
- **Медленно / OOM** — уменьшите `HARNESS_NUM_CTX`, сократите
  `HARNESS_KEEP_ALIVE`, возьмите модель меньшего размера.

Полный список — в `docs/troubleshooting.md`.
